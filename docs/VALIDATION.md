Python 3.12/3.13 checks have not run. The prepared CI workflow is retained only
in the original local checkout, not in the published repository.

## GitHub publication without CI

The `gh` login can create repositories, but its OAuth token lacks `workflow`
scope, so GitHub rejected a push containing `.github/workflows/tests.yml`.
At the user's direction, the published `main` history excludes that workflow.
The file remains in the original local checkout, and the original commits are
preserved on the local-only `local/with-ci` branch. No remote CI runs are claimed.

If CI is authorized later, the existing local workflow can be explicitly added
with `git add -f .github/workflows/tests.yml`, committed, and pushed using
credentials permitted to publish workflows.

## Size/import sample

The initial wheel is approximately **50 kB compressed**. A runtime-only install
contains only these four distributions (including this package):

| Distribution | Version | Installed file bytes, including generated bytecode |
| --- | --- | ---: |
| lerobot-lite | 0.1.0 | ~351,000 |
| feetech-servo-sdk | 1.0.0 | 69,652 |
| pyserial | 3.5 | 721,057 |
| tqdm | 4.70.1 | 455,853 |

About **1.6 MB total**, excluding Python itself, the virtual environment,
development tools, and the separate WebRTC application. A single warm-filesystem
sample imported the package in 38 ms, with 21,688 KiB process peak RSS after
import (the measurement process also imported stdlib diagnostic modules).
These are local observations, not cross-platform guarantees or a comparative
benchmark against a full LeRobot installation.
